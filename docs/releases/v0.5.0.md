**Planning v0.5.0 — gestion des appareils depuis la carte**

Le nouvel onglet **Appareils** permet d’ajouter, modifier, désactiver et supprimer
des appareils, puis de les sélectionner dans chaque programmation. Les
associations techniques sont enregistrées dans l’automatisation Home Assistant
et restent utilisables quand le navigateur est fermé.

Trois types de démarrage sont disponibles :

- **Relais / interrupteur** : choix d’une entité `switch`, activation et confirmation.
- **Script Home Assistant** : appel d’un script préconfiguré sans paramètre.
- **Frech avec contrôle d’entrée** : choix du relais, de l’entrée, du script existant et du numéro de machine.

Un renommage conserve les associations existantes. Un appareil désactivé ou
supprimé bloque les programmations qui le contiennent, sans supprimer ces
événements. La configuration technique est réservée aux administrateurs HA ; les
utilisateurs classiques choisissent les appareils actifs dans leurs programmations.

### Installation et mise à jour

1. Mettre à jour **Planning** vers **v0.5.0** dans HACS, puis recharger complètement
   le navigateur ou l’application Home Assistant.
2. Importer séparément [Planning — appareils configurables](https://github.com/Euro-Locks-Belgium/ha-planning-card/blob/v0.5.0/blueprints/planning-devices.yaml).
3. Créer une automatisation pour le même calendrier. Laisser le catalogue vide et
   conserver **Mode test = activé** pour les premiers essais.
4. Dans l’éditeur de carte, choisir cette automatisation dans **Automatisation des appareils**.
5. Ouvrir **Appareils → Ajouter un appareil**, renseigner ses entités et enregistrer.
6. Choisir les appareils dans les programmations.

```yaml
type: custom:ha-planning-card
calendar: calendar.mon_planning
execution_automation: automation.mon_planning_appareils
```

HACS ne crée pas et ne met pas à jour les automatisations déjà importées. Les
anciens blueprints sont conservés. La nouvelle gestion technique nécessite le
nouveau blueprint `planning-devices.yaml`. Lors d’une migration, vérifier les
sélections des événements existants et remplacer les anciens horaires actifs
avant d’utiliser le nouveau parcours en mode réel.

### Personnalisation

Options inspirées de [Daylight Calendar Card](https://github.com/superdingo101/daylight-calendar-card), disponibles dans **Personnalisation** dans l’éditeur de carte :

- Vues **Mois**, **Semaine** et **Agenda**, vue initiale et bouton Aujourd’hui.
- Densité confortable ou compacte.
- Premier jour lundi/dimanche et affichage facultatif des week-ends.
- Heures au format 12 ou 24 heures.
- Événements avec fond, contour ou repère de couleur, et couleur d’accent.
- Affichage facultatif des noms d’appareils en vues semaine/agenda.

Ces réglages n’altèrent pas les événements ni leurs actions. Aucune dépendance
Daylight n’est chargée à l’exécution ; l’implémentation reste autonome.

### Validation

38 tests de logique, 52 scénarios de blueprint et deux parcours navigateur avec
services simulés. Les tests couvrent les trois types d’appareils, leur persistance,
les droits, la désactivation/suppression, les changements concurrents, les erreurs
réseau, les programmations et les vues personnalisées.

La publication GitHub ne modifie aucune installation Home Assistant et ne commande
aucun appareil.
